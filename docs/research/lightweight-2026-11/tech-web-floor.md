# tech-web-floor：保留网页渲染这条路，最瘦能瘦到什么程度

调研日期 2026-11-26 · 只读调研，未改动仓库；所有实验在 `/tmp/monaco-floor` 下用仓库同款构建配置复现。

## 一、结论（先看这里）

1. **Monaco 裁剪后的地板约 3.0～3.4 MB**（已验证，本机实建）：资源目录从 12.7 MB 降到 3.0 MB（纯文本）或 3.4 MB（保留现有全部在用功能），约 −74%。再往下压不动——Monaco 的对外 API 是一个整体对象，无法按需摇掉，最小核心本身就有 2.6 MB。
2. **裁剪不掉功能**（已验证）：并排 / 单栏、行级与行内高亮、「只看变更」折叠、语法着色、深色与高对比主题，在裁剪版上实测均正常，且与现状版行为一致。丢掉的只有只读差异里用不上的语言服务（报错波浪线、补全、悬停）。
3. **换 CodeMirror 6 能到 0.24～0.97 MB，JS 堆约为 Monaco 的 1/3～1/2，就绪更快**（已验证，无头 Chrome 量级参考）。代价是页面层要重写，并且有两个要处理的点：两门语言的官方语法包缺失、大文件默认配置下差异精度会下降（可调）。
4. **diff2html、git-diff-view 不满足现有功能面**（已验证 / 已读官方说明）：前者无虚拟滚动、无未变更折叠，后者渲染层必须配 React 或 Vue。
5. **无论哪一档网页方案，WebView 的固定成本都还在**：网页内容、GPU、网络三个辅助进程是系统 WebKit 框架自带的（已验证存在于 macOS 26）。空闲内存没有公开数字（未查到，检索配额用尽）。
6. 说明：所有「运行内存 / 首次显示」数字来自桌面版 Chrome 无头模式、单台机器、少量采样，**只代表量级，不是本机 App 的实测**；原生一档我未量测，由原生方案调研给出。

## 三、现状为什么这么重【已验证】

- `Web/MonacoDiff/src/main.js` 第一行整包引入 Monaco 根入口，该入口固定带上 83 门基础语言与 css/html/json/typescript 四门「带语言服务」的语言；又显式引入 4 个语言 worker 加 1 个编辑器 worker。
- 构建工具把每个 worker 和每门语言各拆成一个独立文件，于是出现 ts.worker（5.75 MB）等 5 个 worker（合计 8.0 MB，占 63%）、85 个语言分片（0.52 MB）和一个 3.51 MB 的主包。
- 这些文件平时并不都加载：打开 Swift 文件只加载主包 + 编辑器 worker + 一个几 KB 的语言分片；只有打开 js/ts/css/html/json 文件才会拉起对应的大 worker。**重的首先是包体，其次才是运行时。**
- 用仓库里的锁文件原样重建，得到与仓库内完全一致的 12,724 KB / 94 个文件，确认复现可信。
- 顺带发现一个现有小缺陷：`.mm` 文件给的 languageHint 是 `objective-cpp`，Monaco 0.54 没有这门语言，实际会退成纯文本。

## 四、现在实际用到的编辑器功能【已验证，读未压缩源码】

并排对比、宽度不足 960 时自动切单栏、行级标记、行内字符级高亮、「只看变更」未变更区折叠并可点击展开、按扩展名对约 25 种文件做语法着色、跟随系统深浅色与高对比、等宽字体与自适应布局、打开时定位到第一处差异、无障碍标签、只读。没有用到：编辑、补全、悬停、跳转定义、重命名、小地图、概览标尺。宿主与页面只有三个调用：设置差异内容、切换「只看变更」、设置外观。

## 五、各档细节与风险

**仅裁剪**：做法是改为只引 Monaco 的核心 API，再按需补上折叠、剪贴板、只读提示、右键菜单、查找、行选择等功能和实际用到的语言，去掉全部语言 worker。实测四个构建：纯文本 3.0 MB；加 18 门语言的轻量分词与常用功能 3.2 MB；再加 css/html/json 3.4 MB。打开 TypeScript 文件时不再加载 5.75 MB 的 worker。未实测项：键盘复制、Xcode 之外的真机表现（无头环境取不到编辑器按键复制结果）。

**CodeMirror 6**：`@codemirror/merge` 提供并排合并视图，自带行级 / 行内高亮、未变更区折叠。两个实测发现：
- 默认差异精度参数在 1 万行重复度高的样本上会把 60 余行误标为改动，把 `scanLimit` 调大后恢复精确（耗时无明显变化）。
- 官方语法包覆盖现有 25 种提示中的 18 种，缺 Kotlin、Objective-C（npm registry 逐个核对）。另需注意：语法着色要显式启用默认高亮样式，否则接了语言包也不上色（实测踩到）。

**diff2html**：纯文本版 45 KB JS + 17 KB CSS，带常用语言高亮的官方预构建包 295 KB。但它是「整份渲染成静态网页」，974 KB 文件直接生成 2 万多行页面内容，没有虚拟滚动，也没有未变更折叠；小样本上行内高亮未标出（大样本标出），表现不稳定。最近一次发布 2026-01，仓库最后推送 2026-05。

**git-diff-view**：差异引擎（含高亮）本身约 1.0 MB，且官方说明渲染需配 React 或 Vue 组件包，不适合当前「一个原生页面 + 少量脚本」的形态。维护活跃（最后推送 2026-11-25），但社区规模最小（744 星）。

## 六、WebView 自身的固定成本

- 已验证：macOS 26 的系统 WebKit 框架内带网页内容、GPU、网络三个辅助进程服务，`WebPage` 类型自 macOS 26.0 起可用（Apple 文档）。应用一旦显示网页，这部分成本与网页库大小无关，三档网页方案都要付。
- 未查到公开数据：网页内容进程空闲内存、首次创建网页进程的冷启动耗时（检索配额用尽）。
- 未验证假设：GPU 进程约 35 MB、网络进程约 15 MB 常驻，网页内容进程空载约 30～60 MB。依据是本机 Safari 当前同类进程的常驻均值（GPU 约 36 MB、网络约 15 MB）加一般经验，**不是 NeatGit 的实测**；应用调研时未在运行，按约束我没有代为启动。建议由量测代理在应用打开差异后用进程列表确认实际拉起了哪几个辅助进程及其常驻内存。
- 另有一项与库无关的现有成本：页面通过一个本机回环的内置静态服务加载（worker 必须有网络地址才能启动），裁剪到无语言 worker 后仍需保留编辑器 worker，因此这个服务短期去不掉。
