# 界面交互性能分析（Profiler）与优化

> 适用范围：仓库切换、文件选择、分组展开、刷新、差异模式/布局/折叠、提交与 AI 生成入口。
> 目标：点击处理在 MainActor 上毫秒级返回；后台加载和可见渲染分别量测，不用“已显示加载态”冒充内容已经就绪。

## 一、采集与复跑

### 1. 一键录制

先构建并安装要测的版本，然后执行：

```bash
scripts/profile-interactions.sh /Applications/NeatGit.app 60s
```

录制期间依次点击项目、文件、项目/文件分组、刷新、差异模式、只看变更、布局和折叠行。脚本使用 `open -g`，不会主动把应用抢到前台，也不会自动打开 Instruments。

也可直接测本地构建：

```bash
scripts/profile-interactions.sh .build/e2e-derived/Build/Products/Debug/NeatGit.app 30s
```

产物位于 `build/interaction-profiler/`：

| 产物 | 用途 |
|---|---|
| `interactions-*.trace` | Time Profiler + os_signpost + SwiftUI 的 Instruments 原始录制 |
| `interactions-*-summary.txt/json` | 每个交互的次数、主线程样本数、P50、P95、最大耗时 |
| `interactions-*.log` | 超过 1ms 的区间与缓存命中等关键节点 |
| `interactions-*-signposts.xml` | 统计器输入，保留原始 signpost 便于复查 |
| `interactions-*-toc.xml` | Instruments 数据表目录 |

需要单独重算摘要时：

```bash
python3 scripts/summarize_interactions.py \
  build/interaction-profiler/interactions-YYYYMMDD-HHMMSS-signposts.xml \
  --json build/interaction-profiler/summary.json
```

### 2. 指标口径

- `*.点击处理`：同步事件闭包，目标是亚毫秒到数毫秒；不包含 Git、网络或后台准备。
- `*.主线程应用` / `*.主线程发布`：结果回到 MainActor 后的同步工作，不能混入后台耗时后宣称“主线程很快”。
- `原生差异.可见更新`：从接受渲染请求到内容应用完成，包含异步调度；小文件快速路径也使用同一名字，便于直接对比。
- `Git 命令`、`仓库状态.完整读取`、`差异读取.完整加载`、`AI 提交说明.完整生成`、`提交推送.完整执行`：真实后台/外部工作，允许超过一帧，但不能阻塞点击处理。
- `原生差异.可视区绘制`：TextKit 可视区排版与背景绘制；滚动时会重复出现，不应把单次首屏值当成全部滚动性能。

`InteractionProfiler` 始终发 `OSSignposter` 区间；只有超过 1ms 的区间额外进入持久日志，避免亚毫秒点击承担固定日志写盘成本。统计器同时处理 XML 表内引用、共享时间戳与录制边界处的未配对区间。

Apple 参考：[OSSignposter](https://developer.apple.com/documentation/os/ossignposter)、[Improving app responsiveness](https://developer.apple.com/documentation/xcode/improving-app-responsiveness)。本机 Xcode 27.2 / macOS 26.7 的一次录制提示“Trace file had no SwiftUI data”；Time Profiler 与应用 signpost 数据完整，因此当前摘要不依赖 SwiftUI instrument。

## 二、已实施的优化

### 1. 消除无关界面刷新中的重复工作

- 项目分组只在扫描结果或收藏变化时后台重算；不再随提交说明输入、悬停和文件选择重算。
- 文件智能分组、全文件数组、文件索引、可提交数量随状态快照一次构建；`Equatable` 仍只比较原始文件数组，不重复比较派生索引。
- 文件标识、显示名、相对路径和父目录在创建文件状态时计算一次，不再在标签、无障碍、排序和分组中反复拼接。
- 单文件选择与悬停按索引读取；提交摘要复用快照计数。
- 选择态校正由现有快照版本号驱动，不再每次构造并比较全量文件标识数组。
- 文件悬停只在右侧预览视图内观察，不再刷新整个三栏骨架。

### 2. 差异链路减负

- 文档增加加载版本号，渲染协调器不再为了判断“是否同一文档”比较两份全文。
- 最近 4 种渲染结果使用 LRU 复用；来回切换布局、只看变更和展开状态时不用重建富文本。
- 快速切换会取消旧渲染；渲染循环每 256 行检查取消，旧结果仍受批次号隔离，不能迟到上屏。
- 行号字符串、样式数组和展开键在后台一次生成，主线程只赋值并应用富文本。
- 并排滚动只走系统 bounds 通知，去掉同一滚动的双通道重复联动。
- 小文档快速路径：不超过 256 个对照行且两侧文本合计不超过 64,000 UTF-8 字节时同步准备，避免“准备 0.3ms、调度几十毫秒”。超过任一上限仍走后台。
- 模式切换未命中缓存时保留旧文档直到新结果到达，不再先闪空白。

### 3. 顺带修复的边界

- “只看变更”折叠只替换中间省略行，保留改动前后各 3 行上下文；省略 1 行时展开前后总行数不变。
- Git 短格式 ` M` 的空格暂存状态不再被误判为已暂存。
- 差异模式、文件内容与行号在折叠、展开、快速切换后保持一致。

## 三、实测证据

### 1. 纯计算基线与回归

同一台机器、Debug 构建、固定物料：

| 项目 | 优化前 | 当前 | 说明 |
|---|---:|---:|---|
| 500 个项目分组 | 约 45ms | 约 44ms | 算法量级不变，但已移出常规点击与无关刷新 |
| 2000 个文件智能分组 | 约 70ms | 约 41–42ms | 高频路径字段预计算；快照之后只查缓存 |
| 1 万行差异富文本准备 | 约 33ms | 约 36ms | 含原在主线程执行的派生数组；大文件仍在后台 |

性能回归位于 `NeatGitTests/InteractionPerformanceTests.swift`，使用 XCTest `measure` 保存每轮耗时，不设跨机器绝对耗时硬断言。

### 2. 真实后台窗口点击 + Instruments 摘要

采集对象：临时 Git 仓库、Debug 构建、33 次受保护后台点击。小文档快速路径**之前**的一次完整录制：

| 区间 | P50 | P95 | 最大值 |
|---|---:|---:|---:|
| 选择仓库.点击处理 | 0.096ms | 0.257ms | 0.257ms |
| 选择文件.点击处理 | 0.045ms | 0.083ms | 0.083ms |
| 展开文件差异.点击处理 | 0.028ms | 0.035ms | 0.035ms |
| 差异选择.状态处理 | 0.061ms | 0.103ms | 0.103ms |
| 仓库状态.主线程应用 | 0.045ms | 0.074ms | 0.074ms |
| 原生差异.主线程应用 | 0.634ms | 0.917ms | 0.917ms |
| 原生差异.可视区绘制 | 0.092ms | 0.355ms | 0.416ms |
| 原生差异.可见更新（快速路径前） | 20.833ms | 54.295ms | 54.295ms |

同一录制中，小文档后台准备约 0.264ms，说明当时可见更新的主要剩余成本是异步调度，不是文本计算；这直接促成了上述小文档快速路径。Git 子命令 P95 约 82.8ms，位于后台线程，不计入主线程点击处理。

快速路径加入后：`NativeDiffFastPathTests` 验证小文档在 `render` 返回时已经应用，不再等待异步任务；完整单元/组件测试通过。最后一次窗口复测因 macOS 锁屏在启动前被拒绝，**尚无快速路径后的真实窗口 P50/P95 数字**，不能把快速路径前的数据冒充优化后结果。解锁后按第一节复测即可。

### 3. 回归范围

- 全量 `NeatGitTests` 通过，覆盖原生控件、状态缓存、差异加载/折叠/展开/取消、提交安全、性能量测与主线程差异计算守卫。
- 后台窗口 E2E：9 项通过、1 项按既有原因跳过；33 次真实受保护调用，主窗口像素基线 `diff_ratio = 0`。
- 快速路径后的窗口 E2E 因锁屏未启动；组件级同步完成断言已通过，不把该项列为窗口验收通过。

## 四、剩余边界与下一步

1. Git 进程启动、网络、推送和大文件差异计算天然可能超过一帧；继续要求异步、可取消、旧结果隔离，不用同步等待换“更快”。
2. 大文件 TextKit 排版、超长行与滚动性能需用大物料单独录 Time Profiler；小文档快速路径数据不能外推。
3. 渲染缓存限制为 4 项，若引入更大缓存必须先记录内存增量。
4. 采集本身有开销：亚毫秒分析以 signpost 汇总为准，持久日志只看超过 1ms 的候选热点。
5. 系统锁屏时不降低安全策略、不用组件截图冒充窗口点击；待解锁后补快速路径真实窗口复测。
